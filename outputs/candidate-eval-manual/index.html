Scoring axes

評価は2軸 ＋ 総合判定

Axis ①

求人マッチング度

AI戦略ディレクター求人の要件と、職経の合致度（1〜5）。必須要件＝自立／自律／自励・DX実務2年以上・バイブコーディング継続を主軸に、歓迎要件は加点。

基準: HERP求人 hc2fhcRowLWH ／ requisition_ai_director.md
Axis ②

AI協働適性

生成AI×自動化を本番成果まで持っていく素養（自走・完遂・本番化・継続進化）を1〜5で。"使ったことがある"では加点しない。

基準: 岸野×Claude Code の FUTUREMIND自動化実績群（到達水準アンカー）

各軸のスコアには職経からの具体的な引用を必ず添える（根拠なき点数は禁止）。

The yardstick

②の「ものさし」＝岸野×Claude Code の実績

ワークサンプルが baseline_kishino をアンカーにするのと同じ思想で、岸野が実際にClaude Codeと作ってきた本番自動化を「良いAI協働の到達水準（＝5点）」に置く。

採用自動化24項目

HERP応募→登録、お見送り自動化、評価依頼、SmartHR登録 等の本番稼働。

KOT労務承認Bot

API不可→Playwright UI自動化へ転換。3段階承認を実証。

部門集計／夜間QA

Looker・L-ad集約、全プログラム夜間自動レビュー＋自動修正。

候補者がこの水準に近いAI/自動化の本番実績を職経で示せるほど高得点。素材は anchor_ai_collaboration.md に蒸留（評価を重ねて更新＝成長）。

Verdict

総合判定はしきい値で決定論的に

🟢 面接進出推奨
両軸とも 3.5 以上
🟡 要検討
合格圏未達だが
見送り基準も超え
🔴 見送り
いずれかが 2.0 以下

判定はLLMの気分でなく固定ルールで算出するので毎回ブレない（しきい値は RESUME_PASS_BOTH / RESUME_REJECT_ANY で調整可）。

例：求人マッチ 4.0 ／ AI協働 3.5 → 🟢 面接進出推奨。判定理由も自動で添える。

How to use · A

使い方A：Slackに投下する（基本）

1

#candidate-eval に PDF / DOCX を投下

履歴書または職務経歴書をドラッグ＆ドロップするだけ。

2

候補者を選ぶ

「この書類は誰のもの？」とAI戦略ディレクター候補のドロップダウンが出る → 氏名を選択。

3

採点が走る（数十秒）

氏名__UUID にリネーム＋会話/書類フォルダ格納 → 2軸採点 → 評価Doc生成。

4

結果カードが返る

総合判定＋2軸スコア＋根拠。スレッドに詳細レポート。jobmanager J列にDocリンク自動反映。

※ ファイル名が 氏名__UUID.pdf の形式なら、候補者選択をスキップして直行する。

How to use · B

使い方B：jobmanager I列から取得（CLI）

既にスプシ I列（職務経歴書URL）に職経がある候補者は、投下せず取得して評価できる。

# I列の職経URLから取得して評価 python -m bot.resume_eval --drive '<I列のDrive URL>' --uuid <HERP_candidacy_UUID> --name '氏名' # ローカルのPDF/DOCXから評価 python -m bot.resume_eval --file ./resume.pdf --uuid <UUID> --name '氏名' # 取得・抽出だけ確認（採点・Doc生成・反映なし＝安全） python -m bot.resume_eval --drive '<URL>' --dry
Drive取得は eval-doc GAS の fetch_drive_file 経由（読取専用）。実I列PDFで抽出8301文字を確認済。

Principles

採点の原則（やること・やらないこと）

✓ やること

  • 各スコアに職経からの具体的引用を添える
  • 必須要件3軸への合致を主軸に見る
  • 書類で不足した点は「面接で確認すべき点」に回す
  • 判定はしきい値で決定論的に（毎回ブレない）

✕ やらないこと

  • 書類に無い事項を推測で加点する
  • ワークサンプルの4.83/7軸を書類に混ぜる
  • 「API制限で対象外」と逃げる（完全自動が原則）
  • 根拠なきスコアを出す
確認できない事項は evidence に「書類からは確認不能」と明記する。

01
Executive Summary

このクラスタは何をしているか

🛰️

① 検知する

媒体応募メール・HERP通知・SmartHR通知・スプシの未処理行を、各ボット(b*)が常時ポーリングして「いま動くべき1件」を見つける。

🪪

② 承認をもらう（HITL）

実行内容をSlackの承認カードにして該当チャンネルへ投稿。担当者が ✅ を押すまで外部へは一切送信しない。✏️で文面修正も可。

⚙️

③ 実行する

✅を常駐リスナーが受信し、commit_one()が HERP / Gmail / SmartHR / カレンダー / スプシ へ実際の操作を反映する。

担当者の体験

「Slackで流れてくるカードを確認して✅を押すだけ」。判断は人、作業はボットという役割分担。

守られている原則

全ルート 人間の✅必須・冪等（二重実行防止）・production gate（本番/dry切替）。

カバー範囲

応募受付 → 書類取込 → 評価 → 面接調整 → 内定・入社準備 → お見送り まで採用フロー全段。

※「29項目」= 管理表『採用業務29項目』タブの自動化対象。本資料はその実装＝ボット群の地図。

ルート設定駆動エンジン

全業務は routes.py の ROUTES(23ルート)に1エントリとして宣言される。各ルートは4つの属性を持つだけ。

match

発火条件（このメール／このスプシ行が対象か）

action

実行内容（mail / step_change / calendar / upload など）

channel

承認カードの投稿先 Slackチャンネル

production

本番フラグ。Falseなら✅でも dry-run強制（安全側）

共通の安全弁

お見送りは誤送信の影響が大きいため、✅押下にconfirmダイアログを挟む。HERPの選考終了は専用モーダル（終了理由=不採用）で確定し、失敗してもメール送信は覆さない（best-effort）。

選考終了の自動化

2026-06-18 go-live：お見送り✅後にHERPが自動で「選考終了→不採用」。step_change_production で本番/dryを別ゲート管理。

媒体ボード上の「不採用」操作(#27③ media_reject)は対象外で False据え置き。AI習熟度評価(b21)由来のお見送りは route.production が現在 dry（実候補で検証後 True化）。

Safety · 静かな失敗を防ぐ

クラスタを支える安全設計

🪪 HITL（人間の✅必須）

全ルートで承認なしには外部送信しない。誤検知してもカードが流れるだけで実害なし。お見送りは confirm 二段。

🔁 冪等（二重実行防止）

state.db の processed_messages / bot別マークで、同じ案件を二度処理しない。Slack未達時は processed化せず再送。

🚦 production gate

routes.py の production=True/False で本番/dryを切替。切替後は listener 再起動が必須（routesをメモリ保持するため）。

🩺 scrape 自動アラート

UIスクレイプ依存(HERP/求人BOX/媒体)はDOM変更で静かに止まる → 失敗を notify_scrape_failure で検知通知（3hに1回へ抑止）。月次dry-runで点検。

🔐 認証情報

Keychain(service=hr-mail-bot)に Gmail/Slack/HERP/SmartHRトークンを集約。未登録ボットは起動時に明示エラーで停止（誤動作させない）。

⚠️ 既知の残リスク

#24 ファイル名に氏名が無い返送の取りこぼし／#22 email一意制約(全員jinji_saiyo@)／UIスクレイプ脆弱性。月次ヘルスチェックで監視。
